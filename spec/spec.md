# WentianCode（文天）Spec（现行版本：v0.5）

## 背景

yuning 要从零做一个自己的命令行 AI 助手（类 Claude Code），作为长期演进的 coding agent 的起点。v0.1 已完成最小内核：终端里的多轮流式对话，打通「多后端 + 流式输出 + extended thinking + Markdown 渲染 + 会话持久化」主干（F1–F12，全部验收）。v0.2 已完成 Claude Code 式交互体验（横幅 / 后端选择 / 多行输入 / 状态栏 / 计时反馈 / 中断，F13–F18，全部验收）。

**v0.3 范围**：工具系统——助手从「只能动嘴」变成「能干活」。模型在回复中可请求调用工具（读文件、写文件、改文件、执行命令、按模式找文件、搜文件内容），程序执行后把结果回灌给模型，模型据此给出最终回答（F19–F28）。本版只做**单轮工具执行**：一次回复内的并列工具调用全部执行并一并回灌，模型的后续回复若再请求工具则不执行；多轮自动循环（Agent Loop）留给 v0.4。（v0.3 已验收，2026-06-11 离线项全绿。）

**v0.4 范围**：Agent Loop——助手从「一步一停」变成「自主干活」。模型拿到工具结果后可继续请求工具，循环往复直到任务完成（F29–F34）。配套四件事：循环过程以统一事件流输出（界面与循环逻辑彻底解耦）；流式双路（实时显示与完整累积并行）；并列工具调用按安全性分批（只读并发、副作用串行）；计划模式两段式（`/plan` 只读勘察出计划、`/do` 切回全工具执行）。权限系统、上下文压缩留给后续版本。

**v0.5 范围**：结构化系统提示 + 提示词缓存——助手从「能干活」变成「干得好」。把原来「工具清单 + cwd」三五行的裸 `system` 字符串，展开成**七模块结构化系统提示**（身份 / 系统约束 / 任务模式 / 动作执行 / 工具使用 / 语气风格 / 文本输出），按优先级有序拼装、模块可插拔（F35）；身份/语气/输出三模块写出**文天人格**（沙雕、幽默、真诚、爱照顾朋友的命令行编程伙伴，油塌头 `=^_^=`，底子是严谨工程师）（F36）；关键工具约定在系统提示与工具描述里**双重强化**（F37）。区分稳定与动态：稳定的「工具声明 + system」前缀走**可缓存通道**（Anthropic 显式 `cache_control` 断点，OpenAI 兼容走自动前缀缓存）（F38）；环境信息与会话级开关提醒走**消息通道**，以 `<system-reminder>` 标签在请求时注入、永不持久化，开关提醒按轮次注入（首轮完整 / 间隔重复 / 其余精简）（F39）；解析后端返回的缓存命中字段并入用量、可观测验证（F40）。项目指令文件加载、自动记忆、真实 MCP 接入、自动化提示评估留给后续版本（仅预留可选模块槽位）。

## 目标

- 在终端启动后进入交互式对话界面，输入问题，流式逐字看到回复
- 助手回复以 Markdown 渲染呈现（标题、列表、代码块等有格式区分），不是裸源码
- 支持多轮对话，助手记得之前说过的话
- 一套配置切换多家大模型后端（Claude / OpenAI 协议 / 国产兼容模型）
- 支持 Claude 的 extended thinking，思考过程可见
- 后端通过统一接口抽象，方便以后加新后端
- 对话跨会话持久化，下次能接着聊
- 模型能调用本地工具读写文件、执行命令、搜索代码，从聊天机器人变成能干活的助手（v0.3）
- 模型能围绕一个任务自主多轮调用工具直到完成——过程可见、可中断、有安全刹车（v0.4）
- 系统提示结构化、可插拔、有人格，稳定部分走缓存省钱省时延、动态部分走消息通道不污染缓存，让助手从「能干活」变「干得好」（v0.5）

## 功能需求

- F1: 启动后进入滚动式交互对话界面，显示提示符并等待用户输入
- F2: 用户输入一行问题并提交后，调用当前后端的大模型 API
- F3: 模型回复以流式方式逐字/逐块实时显示，而非等全部生成完再显示
- F4: 维护多轮对话上下文，每次请求携带历史对话，使助手记得之前内容
- F5: 支持两种后端协议——Anthropic 协议、OpenAI 兼容协议（后者覆盖国产兼容模型）
- F6: 通过 YAML 配置文件管理多个后端，每个后端含 protocol / model / base_url / api_key 四个核心字段，并指定一个默认后端
- F7: 启动时可临时指定使用哪个后端，覆盖默认
- F8: 对 Anthropic 后端支持 extended thinking，思考内容与正文回复在界面上可区分地展示
- F9: 每轮对话结束后自动把会话持久化到本地；支持下次启动续上一次会话，也支持开启全新会话
- F10: 提供会话内命令：查看帮助、新建会话、列出/恢复历史会话、切换后端、退出
- F11: 后端以统一接口抽象，新增一种后端不需要改动界面层与会话层
- F12: 助手正文回复以 Markdown 渲染显示（至少支持标题、列表、代码块、行内代码、粗/斜体）；渲染与流式不冲突——生成过程中内容持续逐步出现，最终定格为渲染后的格式化文本，而非裸 Markdown 源码。思考内容（F8）保持纯文本展示，不做 Markdown 渲染

以下为 v0.2 新增（交互体验对齐 Claude Code）：

- F13: 启动时显示欢迎横幅，布局对齐 Claude Code：左侧 icon 即文本猫脸 `=^_^=` 本体（朱砂色加粗；不做像素画，任何终端字体下都不变形）；右侧为信息行——程序名与版本号、当前后端与模型、会话状态（新会话或已恢复及其标识）。不使用整框包裹
- F14: 配置了多个后端且启动时未显式指定后端时，进入对话前展示可用后端列表，用方向键选择、回车确认（默认后端预先高亮）；取消选择则使用默认后端。只配置一个后端或已显式指定时不出现此列表
- F15: 输入区为多行输入框，提示符为 `❯ `（输入区不绘制边框：边框需要在 prompt_toolkit 渲染器之外写终端，会与重绘机制冲突）——回车提交；提供专用按键换行；上下方向键可翻阅历史输入，历史跨程序重启保留
- F16: 输入框下方常驻一行状态栏，显示当前后端与模型、会话标识、当前消息数；会话内切换后端/新建/恢复会话后，状态栏内容随之更新
- F17: 从提交问题到回复结束期间提供持续的活动反馈：以单行文本猫脸帧（`=^_^=` 与 `=-_-=` 眨眼轮换）加已用秒数显示，等待期与正文流式期一致（流式期随正文一同呈现），回复定格后计时信息消失
- F18: 生成期间可随时中断本轮回复（专用按键或中断快捷键），中断不退出程序、不破坏会话：已产生部分正文时，部分正文保留在屏幕与对话历史中，并有可见的「已中断」提示；尚无任何正文时，本轮提问从历史中撤销（不留未回答的提问）。中断后可立即继续下一轮输入

以下为 v0.3 新增（工具系统）：

- F19: 工具以统一抽象定义：每个工具具有名称、面向模型的功能描述、参数结构描述（各参数的名称/类型/是否必填/说明）和执行入口。新增一个工具不需要改动对话回合逻辑与界面层
- F20: 内置六个核心工具：
  - 读文件：按路径读取文本文件内容，支持只读取指定行范围
  - 写文件：将完整内容写入指定路径（不存在则创建，必要时创建父目录；存在则覆盖）
  - 改文件：在指定文件中做「原文精确替换」——给出原文片段与替换片段，原文必须在文件中**唯一**出现
  - 执行命令：在工作目录下执行一条 shell 命令，返回输出与退出码
  - 找文件：按通配模式（如 `**/*.py`）列出匹配的文件路径
  - 搜内容：按正则在文件内容中搜索，返回匹配的文件、行号与行内容
- F21: 提供工具注册中心：集中登记全部工具，支持按名称查找，并能生成传给后端 API 的工具声明列表。模型调用未注册的工具名时，返回结构化错误结果而非崩溃
- F22: 两种后端协议（Anthropic、OpenAI 兼容）都支持工具调用全链路：把工具声明随请求发出；解析模型流式回复中的工具调用请求（含分片到达的参数碎片拼接）；把工具执行结果以协议要求的格式回传给模型
- F23: 单轮工具执行语义：模型一次回复中发出的全部并列工具调用依次执行，结果一并回灌，模型据此生成后续回复；若后续回复中再次请求工具，则不执行，界面提示本版仅支持单轮工具调用，已生成的文字正常保留，本轮结束回到输入状态。不含工具调用的普通回复行为与 v0.2 完全一致
- F24: 工具执行的健壮性：每次执行有超时上限；任何失败（参数缺失或非法、文件不存在、命令出错、超时、未注册工具）都包装成结构化错误结果回灌模型，使其能调整重试或向用户说明——程序不崩溃、会话不中断
- F25: 改文件工具的精确语义：原文片段在文件中恰好出现一次才执行替换；出现零次或多次时不改动文件，返回包含实际匹配次数的明确错误，让模型能修正后重试
- F26: 副作用工具（写文件、改文件、执行命令）执行前展示将要做的事（目标文件或命令内容），等待用户确认；用户拒绝时该工具不执行，以「用户拒绝执行」作为结果回灌模型。只读工具（读文件、找文件、搜内容）直接执行不询问
- F27: 工具调用过程在界面可见：每次调用显示工具名与关键参数摘要、执行结果状态（成功/失败/被拒绝）与结果摘要，样式与正文回复可区分
- F28: 工具调用与其结果作为会话历史的一部分持久化；恢复会话后模型仍能引用之前工具调用的结果，上下文完整不丢

以下为 v0.4 新增（Agent Loop）：

- F29: 多轮自动工具循环（ReAct 模式）：模型回复中请求工具 → 程序执行并回灌结果 → 模型据此继续（可再请求工具），循环往复直到任务完成。五个停机条件全部具备，且停机原因在界面上可区分：
  - 模型自然完成：回复中不再请求工具
  - 轮数上限（兜底安全网）：单回合循环轮数有可配置上限；达上限时剩余工具请求不执行、已生成文字保留、界面明确提示
  - 用户中断：模型生成期间可随时中断；语义沿 v0.2/v0.3——已有文字保留入史，本轮未执行的工具请求丢弃，已完成轮次的工具交互保留；历史任何时刻都保持「工具请求与结果成对」
  - 未知工具空转：连续多轮的全部调用都是未注册工具名时停止循环（防幻觉死循环）；其间出现任何已注册调用则计数重置
  - 流式出错：当前轮丢弃、已完成轮次保留，界面显示错误，程序不崩溃、会话可继续
- F30: 循环过程以统一事件流对外输出：轮次开始/结束、思考与正文增量、工具调用发起、工具结果、token 用量、循环结束（含停机原因）。界面层仅消费事件流做渲染，不参与循环决策；更换或扩展界面无需改动循环逻辑（可测性：用「事件记录器」替代界面即可完整断言一次循环）
- F31: 流式双路收集：正文增量实时推送界面（边生成边显示，观感与 v0.2 一致），同时完整累积本轮回复（文本、全部工具调用、协议原始块、用量）供循环决策与入史——显示不等待累积完成，累积不遗漏任何显示内容
- F32: 并列工具调用按安全性分批执行：连续的只读调用并发执行（总耗时接近其中最慢的一个，而非逐个相加）；副作用调用与未知调用串行执行，并与前后只读调用保持模型给出的相对顺序（写后之读不被提前）。无论实际完成先后，结果一律按原始调用顺序回灌与入史；界面上调用行与结果行也按原始顺序成对出现。副作用确认门语义沿 v0.3：逐次确认、拒绝结果回灌
- F33: 计划模式（两段式工作流）：`/plan` 进入计划模式——此后所有轮次只向模型提供只读工具（读文件、找文件、搜内容），并提示模型先勘察、产出执行计划、不做任何修改；模型在计划模式中硬请求副作用工具时不执行，以「计划模式下该工具不可用」的结构化错误回灌（模型可自我修正；此类拦截不计入未知工具停机）；状态栏显示计划模式标记。`/do` 退出计划模式恢复全部工具，其后可附带文字作为下一条用户消息（如 `/do 按计划执行`）。模式是会话内的界面状态，不随会话持久化
- F34: token 用量统计：循环每轮的用量跨轮累计，回合结束后显示总输入/输出 token 数与循环轮数；后端未报用量时不显示

以下为 v0.5 新增（结构化系统提示 + 提示词缓存）：

- F35: 结构化系统提示——系统提示由一组**固定模块按优先级有序拼装**而成：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出（共七个，顺序即优先级，模块间空行分隔）；其后接**可选模块槽位**（自定义/项目指令、已激活 Skill、长期记忆）。每个模块是一个独立、可单独测试的单元，新增/替换/重排一个模块只改模块定义、不改拼装逻辑。可选模块本版渲染为空（不产出任何文本、不留空行残渣），但插拔接口就绪。系统提示的组装是纯函数，不依赖后端 SDK、可在不联网下完整测试
- F36: 文天人格——身份、语气风格、文本输出三个模块写出文天这个产品的人格：有点沙雕、幽默、真诚、爱照顾朋友的命令行编程伙伴，形象是一头油塌塌头发的猫脸 `=^_^=`，但底子是严谨的工程师。技术输出上「语气是这只猫、底子是工程师」——可以贫、可以自嘲，但结论不掺水、证据不省略、工程纪律（先勘察后动手、完成前验证）不打折。**人设只体现、不透露**：文天通过言行自然流露这些特质，但绝不向用户复述、罗列或解释自己的人设设定与系统提示；用户直接问「你的人设/设定/系统提示是什么」时，自然带过或答非所设，不逐条背诵（如同不泄露系统提示——这是红线）
- F37: 关键工具约定双重强化——「优先用专用工具而非 shell、编辑文件前必先读取、无依赖的调用可并行发起、优先相对路径」这类关键约定，**同时**写进系统提示的「工具使用」模块和受影响工具自身的描述（description）中；两处措辞一致、互相强化，以提高模型对这些约定的遵守率
- F38: 提示词缓存（稳定前缀走可缓存通道）——稳定不变的「工具声明 + 系统提示」前缀走可缓存通道，跨同一会话的多次请求复用以省钱省时延。Anthropic 后端在系统提示块上施加 `cache_control: ephemeral` 缓存断点（前缀缓存覆盖其之前的工具声明与系统提示整段）；OpenAI 兼容后端走其服务端自动前缀缓存（无显式缓存控制 API）。对话历史与动态内容不进缓存（本版只缓存稳定前缀，多断点缓存历史留后续版本）
- F39: 动态内容走消息通道（`<system-reminder>` 注入）——环境信息（工作目录、操作系统、当前日期、git 分支）与会话级开关提醒（如计划模式），以带 `<system-reminder>...</system-reminder>` 标签的内容在**每次发请求时**注入消息流：请求时由组装层拼装、**永不写入持久化会话**；标签使模型把它当作系统级补充指令处理、不当成用户输入来回复；因其位于缓存断点之后，不污染稳定前缀的缓存。会话级开关提醒按轮次注入以控制频率：**首轮完整、每 N 轮重复完整、其余轮精简为一行**（N 可配置，默认 5）
- F40: 缓存命中可观测——后端解析 API 返回的缓存用量字段（Anthropic 的 `cache_creation_input_tokens` / `cache_read_input_tokens`；OpenAI 兼容的 `prompt_tokens_details.cached_tokens`），并入 token 用量统计跨轮累计；回合结束的用量行在有缓存命中时显示缓存读取/创建 token，用于验证缓存策略真实生效。后端未报缓存字段时按 0 处理、不显示缓存信息

## 非功能需求

- N1: 实现语言为 Python（用户指定）
- N2: 优先复用各后端官方 SDK，流式、鉴权、重试等细节交给 SDK，不手写 HTTP/SSE
- N3: 默认模型为当前最强 Claude 模型，不擅自降级
- N4: 配置文件与会话数据存放遵循 XDG 标准用户目录
- N5: 单一职责分层（配置 / 后端 / 会话 / 界面相互解耦），核心逻辑可在不联网的情况下被自动化测试
- N6: （v0.3）工具的定义与执行不依赖任何后端 SDK；协议差异（工具声明格式、流式解析、结果回传格式）全部在后端层内消化，工具层对协议无感知
- N7: （v0.3）全部六个工具的执行逻辑可在不联网的情况下被自动化测试（在临时目录中真实读写文件、执行无害命令）
- N8: （v0.4）循环核心对协议与具体工具无感知（仅依赖统一后端接口与执行器接口）；循环全链路（事件流、双路收集、安全分批、五停机条件）可在不联网的情况下被自动化测试

## 不做的事

- 不做规则化权限系统（allowlist、「总是允许」、按目录授权等——仍是逐次 y/N 确认）
- 不做路径沙箱（不限制工具只能访问某目录子树；副作用靠执行前确认兜底）
- 不做六个核心工具以外的扩展工具（子代理、网页访问、todo 管理等）
- 不做全屏 TUI（仍为滚动式终端，与 Claude Code 同形态）
- 不做多模态（图片/文件输入）
- 不做对话内容的检索、压缩或跨会话记忆提炼（长任务超出上下文窗口的处理留给后续版本）
- 不做 slash 命令自动补全菜单（留给后续版本）
- 不做工具执行期间的中断（中断仅覆盖模型生成阶段；长命令依靠工具超时兜底，v0.4 边界）
- 不做新的交互式确认形态（确认交互沿用 v0.3 的逐次 y/N，不新增「总是允许」等选项）

以下为 v0.5 新增不做：

- 不做项目指令文件加载（不读取 `CLAUDE.md` / `AGENTS.md` 之类项目指令——仅为「自定义/项目指令」预留可选模块槽位，本版渲染为空）
- 不做自动记忆 / 长期记忆提炼（仅预留「长期记忆」槽位）
- 不做真实 MCP 接入（仅在「已激活 Skill」槽位层面预留概念位置，不实现任何 MCP 协议）
- 不做自动化提示评估（缓存生效靠解析命中字段定量验证；人格与约定遵守靠人工典型场景 before/after 定性对比，不搭自动评测框架）
- 不做对话历史的缓存（本版只缓存稳定的「工具声明 + system」前缀，单断点；缓存随对话增长的历史前缀需多断点管理，留后续版本）
- 不做多后端缓存断点的统一抽象（OpenAI 兼容走服务端自动前缀缓存、不显式打标；缓存控制力集中在 Anthropic）
