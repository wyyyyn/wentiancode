# WentianCode（文天）Spec（现行版本：v0.3）

## 背景

yuning 要从零做一个自己的命令行 AI 助手（类 Claude Code），作为长期演进的 coding agent 的起点。v0.1 已完成最小内核：终端里的多轮流式对话，打通「多后端 + 流式输出 + extended thinking + Markdown 渲染 + 会话持久化」主干（F1–F12，全部验收）。v0.2 已完成 Claude Code 式交互体验（横幅 / 后端选择 / 多行输入 / 状态栏 / 计时反馈 / 中断，F13–F18，全部验收）。

**v0.3 范围**：工具系统——助手从「只能动嘴」变成「能干活」。模型在回复中可请求调用工具（读文件、写文件、改文件、执行命令、按模式找文件、搜文件内容），程序执行后把结果回灌给模型，模型据此给出最终回答（F19–F28）。本版只做**单轮工具执行**：一次回复内的并列工具调用全部执行并一并回灌，模型的后续回复若再请求工具则不执行；多轮自动循环（Agent Loop）留给 v0.4。

## 目标

- 在终端启动后进入交互式对话界面，输入问题，流式逐字看到回复
- 助手回复以 Markdown 渲染呈现（标题、列表、代码块等有格式区分），不是裸源码
- 支持多轮对话，助手记得之前说过的话
- 一套配置切换多家大模型后端（Claude / OpenAI 协议 / 国产兼容模型）
- 支持 Claude 的 extended thinking，思考过程可见
- 后端通过统一接口抽象，方便以后加新后端
- 对话跨会话持久化，下次能接着聊
- 模型能调用本地工具读写文件、执行命令、搜索代码，从聊天机器人变成能干活的助手（v0.3）

## 功能需求

- F1: 启动后进入滚动式交互对话界面，显示提示符并等待用户输入
- F2: 用户输入一行问题并提交后，调用当前后端的大模型 API
- F3: 模型回复以流式方式逐字/逐块实时显示，而非等全部生成完再显示
- F4: 维护多轮对话上下文，每次请求携带历史对话，使助手记得之前内容
- F5: 支持两种后端协议——Anthropic 协议、OpenAI 兼容协议（后者覆盖国产兼容模型）
- F6: 通过 YAML 配置文件管理多个后端，每个后端含 protocol / model / base_url / api_key 四个核心字段，并指定一个默认后端
- F7: 启动时可临时指定使用哪个后端，覆盖默认
- F8: 对 Anthropic 后端支持 extended thinking，思考内容与正文回复在界面上可区分地展示
- F9: 每轮对话结束后自动把会话持久化到本地；支持下次启动续上一次会话，也支持开启全新会话
- F10: 提供会话内命令：查看帮助、新建会话、列出/恢复历史会话、切换后端、退出
- F11: 后端以统一接口抽象，新增一种后端不需要改动界面层与会话层
- F12: 助手正文回复以 Markdown 渲染显示（至少支持标题、列表、代码块、行内代码、粗/斜体）；渲染与流式不冲突——生成过程中内容持续逐步出现，最终定格为渲染后的格式化文本，而非裸 Markdown 源码。思考内容（F8）保持纯文本展示，不做 Markdown 渲染

以下为 v0.2 新增（交互体验对齐 Claude Code）：

- F13: 启动时显示欢迎横幅，布局对齐 Claude Code：左侧 icon 即文本猫脸 `=^_^=` 本体（朱砂色加粗；不做像素画，任何终端字体下都不变形）；右侧为信息行——程序名与版本号、当前后端与模型、会话状态（新会话或已恢复及其标识）。不使用整框包裹
- F14: 配置了多个后端且启动时未显式指定后端时，进入对话前展示可用后端列表，用方向键选择、回车确认（默认后端预先高亮）；取消选择则使用默认后端。只配置一个后端或已显式指定时不出现此列表
- F15: 输入区为多行输入框，提示符为 `❯ `（输入区不绘制边框：边框需要在 prompt_toolkit 渲染器之外写终端，会与重绘机制冲突）——回车提交；提供专用按键换行；上下方向键可翻阅历史输入，历史跨程序重启保留
- F16: 输入框下方常驻一行状态栏，显示当前后端与模型、会话标识、当前消息数；会话内切换后端/新建/恢复会话后，状态栏内容随之更新
- F17: 从提交问题到回复结束期间提供持续的活动反馈：以单行文本猫脸帧（`=^_^=` 与 `=-_-=` 眨眼轮换）加已用秒数显示，等待期与正文流式期一致（流式期随正文一同呈现），回复定格后计时信息消失
- F18: 生成期间可随时中断本轮回复（专用按键或中断快捷键），中断不退出程序、不破坏会话：已产生部分正文时，部分正文保留在屏幕与对话历史中，并有可见的「已中断」提示；尚无任何正文时，本轮提问从历史中撤销（不留未回答的提问）。中断后可立即继续下一轮输入

以下为 v0.3 新增（工具系统）：

- F19: 工具以统一抽象定义：每个工具具有名称、面向模型的功能描述、参数结构描述（各参数的名称/类型/是否必填/说明）和执行入口。新增一个工具不需要改动对话回合逻辑与界面层
- F20: 内置六个核心工具：
  - 读文件：按路径读取文本文件内容，支持只读取指定行范围
  - 写文件：将完整内容写入指定路径（不存在则创建，必要时创建父目录；存在则覆盖）
  - 改文件：在指定文件中做「原文精确替换」——给出原文片段与替换片段，原文必须在文件中**唯一**出现
  - 执行命令：在工作目录下执行一条 shell 命令，返回输出与退出码
  - 找文件：按通配模式（如 `**/*.py`）列出匹配的文件路径
  - 搜内容：按正则在文件内容中搜索，返回匹配的文件、行号与行内容
- F21: 提供工具注册中心：集中登记全部工具，支持按名称查找，并能生成传给后端 API 的工具声明列表。模型调用未注册的工具名时，返回结构化错误结果而非崩溃
- F22: 两种后端协议（Anthropic、OpenAI 兼容）都支持工具调用全链路：把工具声明随请求发出；解析模型流式回复中的工具调用请求（含分片到达的参数碎片拼接）；把工具执行结果以协议要求的格式回传给模型
- F23: 单轮工具执行语义：模型一次回复中发出的全部并列工具调用依次执行，结果一并回灌，模型据此生成后续回复；若后续回复中再次请求工具，则不执行，界面提示本版仅支持单轮工具调用，已生成的文字正常保留，本轮结束回到输入状态。不含工具调用的普通回复行为与 v0.2 完全一致
- F24: 工具执行的健壮性：每次执行有超时上限；任何失败（参数缺失或非法、文件不存在、命令出错、超时、未注册工具）都包装成结构化错误结果回灌模型，使其能调整重试或向用户说明——程序不崩溃、会话不中断
- F25: 改文件工具的精确语义：原文片段在文件中恰好出现一次才执行替换；出现零次或多次时不改动文件，返回包含实际匹配次数的明确错误，让模型能修正后重试
- F26: 副作用工具（写文件、改文件、执行命令）执行前展示将要做的事（目标文件或命令内容），等待用户确认；用户拒绝时该工具不执行，以「用户拒绝执行」作为结果回灌模型。只读工具（读文件、找文件、搜内容）直接执行不询问
- F27: 工具调用过程在界面可见：每次调用显示工具名与关键参数摘要、执行结果状态（成功/失败/被拒绝）与结果摘要，样式与正文回复可区分
- F28: 工具调用与其结果作为会话历史的一部分持久化；恢复会话后模型仍能引用之前工具调用的结果，上下文完整不丢

## 非功能需求

- N1: 实现语言为 Python（用户指定）
- N2: 优先复用各后端官方 SDK，流式、鉴权、重试等细节交给 SDK，不手写 HTTP/SSE
- N3: 默认模型为当前最强 Claude 模型，不擅自降级
- N4: 配置文件与会话数据存放遵循 XDG 标准用户目录
- N5: 单一职责分层（配置 / 后端 / 会话 / 界面相互解耦），核心逻辑可在不联网的情况下被自动化测试
- N6: （v0.3）工具的定义与执行不依赖任何后端 SDK；协议差异（工具声明格式、流式解析、结果回传格式）全部在后端层内消化，工具层对协议无感知
- N7: （v0.3）全部六个工具的执行逻辑可在不联网的情况下被自动化测试（在临时目录中真实读写文件、执行无害命令）

## 不做的事

- 不做多轮自动工具循环（Agent Loop——模型拿到工具结果后还能继续调工具直到完成任务，留给 v0.4）
- 不做规则化权限系统（allowlist、记住选择、按目录授权等，仅逐次 y/n 确认）
- 不做路径沙箱（不限制工具只能访问某目录子树；副作用靠执行前确认兜底）
- 不做六个核心工具以外的扩展工具（子代理、网页访问、todo 管理等）
- 不做全屏 TUI（仍为滚动式终端，与 Claude Code 同形态）
- 不做多模态（图片/文件输入）
- 不做对话内容的检索、压缩或跨会话记忆提炼
- 不做 slash 命令自动补全菜单（留给后续版本）
- 不做 token 用量展示（留给后续版本）

## 验收标准

- AC1: （F1/F2）启动后能看到提示符，输入问题回车后程序发起一次模型请求
- AC2: （F3）回复在终端逐字/逐块出现，可观察到流式效果，而非一次性整段出现
- AC3: （F4）第二轮提问引用第一轮内容（如「我刚问的是什么」），助手能正确回应，证明上下文被保留
- AC4: （F5/F6/F7）同一份配置下，切换到不同 provider（至少 Anthropic 与一个 OpenAI 兼容后端）都能正常对话；启动时指定 provider 生效
- AC5: （F8）使用 Claude 后端且开启 thinking 时，界面上能区分地看到思考过程与最终回复
- AC6: （F9）一次会话结束退出后，重新启动并选择「续上次」能看到并接续之前的对话历史；选择「新建」则是空白会话
- AC7: （F10）会话内命令均生效：帮助、新建、列出/恢复、切换后端、退出
- AC8: （F11）新增一个「假后端」（实现统一接口）即可被界面层使用，无需修改界面层/会话层代码
- AC9: （N5）在不真实联网的前提下，核心流程（配置解析、后端选择、会话存读、界面循环）可被自动化测试覆盖
- AC10: （F12）让模型输出一段含标题、列表、代码块的回复，终端上最终显示为渲染后的格式（代码块有可区分样式，列表/标题有格式），而非裸 Markdown 源码；且生成过程中能观察到内容逐步出现（流式不丢）

以下为 v0.2 新增：

- AC11: （F13）启动后第一屏可见横幅：左侧 `=^_^=` 猫脸，右侧依次为程序名+版本、后端与模型名、会话状态；整体无边框面板。用 `--continue` 启动时显示「已恢复」及会话标识
- AC12: （F14）配置两个以上后端且不带 `-p` 启动 → 出现后端选择列表，按方向键高亮移动、回车后用所选后端对话；带 `-p` 启动或配置只有一个后端 → 不出现列表直接进入对话
- AC13: （F15）提示符 `❯ ` 后按专用换行键产生第二行（提交内容含换行），回车一次性提交；按 ↑ 能回到上一条输入；重启程序后 ↑ 仍能翻出上次运行的输入历史；连续空回车不在屏幕上残留边框/杂线
- AC14: （F16）启动后状态栏显示后端、模型、会话标识、消息数；执行 /provider 切换后状态栏后端随之变化；对话一轮后消息数增加
- AC15: （F17）提交一个需要较长思考的问题，等待期间可见 `=^_^=` 随时间眨眼、伴随递增秒数；正文开始流式后下方一行同样可见；回复定格后计时信息不再显示
- AC16: （F18）正文流式过程中按中断键：输出立即停止、屏幕保留已生成部分并显示「已中断」提示、程序回到输入状态；此后追问上一轮内容，助手能引用被中断的部分正文（证明部分正文入史）。在首字出现前按中断键：直接回到输入状态，会话历史中无该轮提问

以下为 v0.3 新增：

- AC17: （F19/F21）注册一个「假工具」（实现统一工具抽象）后：它出现在发给后端的工具声明列表中、可按名查找、可被执行——全程无需改动对话回合逻辑与界面层代码（自动化测试验证）
- AC18: （F20/F22）两种后端协议各实测一次：让模型读取一个真实存在的文件并总结内容，界面上可见工具调用发生，最终回答与文件实际内容一致（证明声明、流式解析、结果回传全链路打通）
- AC19: （F23）让模型在一次回复中同时读两个文件 → 两次工具执行都发生，最终回答同时引用两个文件的内容；诱导模型在拿到结果后继续调用工具 → 第二次工具请求不被执行，界面出现单轮限制提示，程序回到输入状态
- AC20: （F24）分别诱发：读不存在的文件、调用不存在的工具名、执行一条会超时的命令 → 程序均不崩溃，模型收到错误信息并能在最终回复中向用户说明
- AC21: （F25）改文件三种情形：原文唯一匹配 → 文件被正确替换；零匹配 / 多处匹配 → 文件未被改动，模型收到含实际匹配次数的错误信息
- AC22: （F26）模型请求写文件或执行命令时，界面出现确认提示并展示将做的事；选择拒绝 → 文件系统无变化/命令未执行，模型的最终回复中体现「被用户拒绝」；只读工具执行时无确认提示
- AC23: （F27）工具执行时界面显示工具名、参数摘要与结果状态，与正文回复样式可区分
- AC24: （F28）完成一轮含工具调用的对话后退出，`--continue` 恢复会话并追问之前工具读到的内容 → 模型能正确引用（证明工具交互入史并持久化）
