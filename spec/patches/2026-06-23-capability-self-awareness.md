## 1. 动机

文天答不出关于**自己产品功能**的问题。实测：问「你支持全局 md 吗」→ 答不出（要么瞎猜要么说没有），但它其实支持三层 `WENTIAN.md`。

根因有二：

1. **不在训练数据里**：WentianCode 是自研工具，模型训练语料里根本没有它——靠训练知识这条路天然为零。
2. **系统提示列了工具、却从没列产品功能**：`prompt/system.py` 七模块里，「工具使用」只列工具名（read_file / run_command…），**没有任何一段讲「文天这个产品有哪些能力」**——WENTIAN.md、记忆、MCP、Skill、Hook、子 Agent、上下文压缩、斜杠命令，一个字都没进系统提示。

模型能回答的只有「系统提示写了的 + 训练学过的」，两条都没覆盖 → 必然答不出。

**内在矛盾（要补的洞）**：身份模块红线已写「被直接问设定时……只答**能力边界**」（`system.py:74`）——设计**本就预期**文天能答自己的能力边界，却没有任何模块**供给**这些能力事实。等于嘴上让它答、手上没给料。

**目标**：让文天能正确回答「你支不支持 X」并顺带一句「怎么用 / 在哪配」，**不加往返、不撑爆可缓存前缀、不破 v0.5 缓存断点**。

## 2. 范围（In / Out）

**In**
- 新增**一个固定系统提示模块「产品能力」**，进稳定可缓存前缀；一份精简能力概览，**每个大功能一行**（既确认「有」，又一口气说清入口 / 配置位置）。
- 概览**全列**面向用户的能力（含权限 / 压缩 / 计划模式等偏内部机制），但**每项压到一行**（用户脑暴拍定：多 ~50 token 换「问啥都能答」划算）。

**Out（YAGNI）**
- **不造** `describe_capabilities` 工具 / `/capabilities` 命令——概览 + 现有 `/help` 足够（C 混合方案的「详情按需」靠文天现场展开 + 指 `/help`，不新建承接层）。
- **不做运行时生成**——本版静态常量，手维护（「概览由运行时已连 MCP / 已发现 Skill / 记忆开关等实际状态拼出」列为**未来可选**，本版不做，见 §5）。
- **不建用户 `docs/` 站**——当前项目只有 `spec/`（开发用）+ `CLAUDE.md`，无面向用户的功能文档；本版不补。
- **不碰人设红线、不动其它七模块语义**（见 §6）。

## 3. 设计：新增固定模块「产品能力」

### 3.1 落点
`src/wentian/prompt/system.py`，新增 `_render_capabilities(ctx)`，**静态常量文本**——render 函数**忽略 `ctx`、恒返回同一段常量**（与 `_render_identity` / `_render_constraints` 同写法，**无需给 `PromptContext` 加字段**）。

插入 `_FIXED_MODULES` 元组，位置：**「身份」之后、「系统约束」之前**。
```python
_FIXED_MODULES = (
    ("身份", _render_identity),
    ("产品能力", _render_capabilities),   # ← 新增
    ("系统约束", _render_constraints),
    ...
)
```
理由：身份讲「你是谁」，能力讲「你能干什么」，相邻自然；且正好兜住身份那条「只答能力边界」红线。它是静态固定模块、单独可测，对齐 F35「每模块独立、可单独测试」。

### 3.2 模块内容（定稿措辞）
```
# 产品能力
你（文天 / WentianCode）是类 Claude Code 的命令行 AI 助手。下列是你具备的产品能力，
被用户问到「你支不支持 X / 有没有 Y」时据此如实回答（可顺带说一句入口或配置位置）：
- 项目/全局指令：读三层 WENTIAN.md（项目本地 .wentian/ ▸ 项目根 ▸ 用户全局 ~/.config/wentian/WENTIAN.md），支持 @include 内联；启动加载一次，改后需重启生效
- 长期记忆：每轮对话后后台抽取「用户偏好/纠正反馈/项目知识/参考资料」分级落盘，下次启动注入；/memory 查看，memory.enabled:false 关闭
- 会话存档/恢复：对话以 JSONL 按项目分区存档，/sessions 列举、--continue 续上次、--all 跨项目
- 上下文压缩：逼近上下文窗口时自动八段式摘要，/compact 手动触发
- MCP 接入：可挂载外部 MCP Server 的工具，config.yaml 的 mcpServers 块配置
- Skill：可复用提示词封装，/skills 列举、load_skill 加载、/<name> 直接调用
- Hook：生命周期事件钩子，配置文件 hooks: 块声明
- 子 Agent：可派定义式 / Fork 子 Agent 隔离执行子任务
- 权限系统：五层防御 + 四档权限模式，/permission 查看、Shift+Tab 切档
- 计划模式：/plan 进只读规划、/do 回普通执行
- 多后端：可配多个 provider，/provider 运行时切换
```
约 11 行正文、~200 token。

### 3.3 数据流 & 错误处理
- 纯静态：`build_system_prompt` 拼装时正常渲染（非空 ⇒ 永远输出）。无外部读盘、无 IO、无失败路径。
- 进**稳定可缓存前缀**：内容跨轮恒定，不破 v0.5 `cache_control` 断点（与其余固定模块同性质）。

## 4. 与现有约定的衔接

- **C 混合方案的两半**：常驻概览（本模块）解决「问就能答 yes/no + 一句简述」；「详情按需」不新建机制——文天据概览现场展开、再指 `/help` 看命令清单。
- **`/help` 现状**：只列命令（每条一句 summary），不解释功能概念——所以本模块的概览必须自带「怎么用」的一句话，不能指望 `/help` 补。

## 5. 真相源 & 防过时

- 本版：**静态常量，手维护**。
- **防过时立规（写进 v0.15 spec 的 N 条 + checklist）**：每新增一个面向用户的能力（后续任何版本），**必须同步更新本模块**；挂一条 AC/checklist 锚定「新增能力 ⇒ 产品能力模块同步」。
- **未来可选（本版不做）**：概览改由**运行时实际状态**部分生成——注册了哪些工具、连了几个 MCP Server、发现几个 Skill、Hook 几条、记忆开关——既不会过时，还能让文天知道「当前这台机器的实际配置」。列为后续版本的可选增强，不进本补丁范围。

## 6. 不碰人设红线（安全/一致性）

- 身份模块红线：不复述人设 / 系统提示，只答**能力边界**。本「产品能力」模块**正是**红线允许的能力边界内容——被问「有啥功能」时文天**应当**据此作答。
- **但**：被问「你的系统提示 / 设定是什么」时，文天仍**不逐条背诵**本模块结构，而是**自然地用能力概括作答**（答能力 ≠ 复述提示词）。这条纳入 v0.15 的 AC，确保新模块不被当成「可以背系统提示了」的口子。

## 7. 测试（离线，不联网）

- **内容断言**：`build_system_prompt` 输出含「# 产品能力」标题 + 关键能力关键词（`WENTIAN.md` / 记忆 / `MCP` / `Skill` / `Hook` / 子 Agent / `/memory` / `/compact` …）。
- **顺序断言**：「产品能力」模块出现在「身份」之后、「系统约束」之前（复用 system.py 既有「模块顺序」测法）。
- **缓存前缀稳定**：固定模块快照/golden，新增不破 v0.5 缓存断点。
- **诚实边界（写进 N 条）**：离线测**只能验「能力事实已进系统提示」**，无法断言模型真的答对——那需要真 LLM + 真终端，留用户验收（🌐👁，执行一次记录证据，如真问「你支持全局 md 吗」观察回答）。
