# v0.9 记忆与会话 — 设计稿（脑暴产出 / 四文档生成的唯一事实来源）

> 本文是 v0.9 脑暴的最终设计稿，也是把 v0.9 写进四份 spec 文档（spec/plan/task/checklist）的**钉死的内容来源**。
> 所有 ID、决策、接口、集成点在此固定；四份文档的作者只负责把这些内容按各自房屋风格落进对应文档。
> 房屋风格以各文档的 **v0.8 节**为范本（同等密度与严谨度）。

## 一句话

文天从「每次失忆」变「越用越懂你」。三套机制 = **项目指令文件** + **会话存档(JSONL)+恢复卫生** + **自动记忆**，分别填 v0.5 就留好的 `项目/自定义指令` 与 `长期记忆` 两个空槽，会话层做 JSONL 重构。

## 与 v0.8 的边界与复用（前置已满足）

- v0.8 = **会话内**上下文压缩（已实现，905 测试全绿、`0.8.0`、clean tree），并**显式声明「不做跨会话记忆提炼」——正好留给 v0.9**。
- v0.9 **复用 v0.8 `context` 包，绝不重造**：
  - `context/estimator.py`：`char_estimate(messages, char_per_token)` / `estimate_total(prompt_total, new_messages, char_per_token)`（纯函数）→ 记忆索引体积预算、会话恢复溢出判定。
  - `context/compactor.py`：`Compactor(provider, *, artifacts_dir, context_window, cfg)`，`.compact(messages, last_usage, *, manual=False) -> CompactionResult`、`.set_provider(...)`、`.set_artifacts_dir(...)` → 会话恢复「token 超限先压一次」**直接调它**。
  - `Provider.prompt_token_total(usage)` → token 口径已在 provider 层统一。
- v0.8 **没碰 `session.py`**，JSONL 重构干净无冲突。
- **provider.stream() 是同步生成器**（summarizer 用普通 `for event in provider.stream(...)` 迭代）→ 记忆抽取器在后台线程里**同步**调用，照搬 summarizer 模式，**不引 asyncio**。
- v0.8 卸载产物在 `<sessions_dir>/<session_id>.artifacts/`；v0.9 把 `sessions_dir` 改为按 cwd 分区后，产物**自动随会话同分区**。

## 已定决策（用户拍板）

1. **会话存储 = 参考 Claude Code**：全局目录**按 cwd 分区** — `~/.local/share/wentian/projects/<cwd-slug>/sessions/<id>.jsonl`（`<cwd-slug>` = 绝对 cwd 路径把分隔符 `/`→`-`，与 Claude Code 同法、可读可调试）。`/sessions` 与 `--continue` **默认只看当前项目分区**，`/sessions --all` 看全部分区。旧全局扁平 `~/.local/share/wentian/sessions/*.json` 视为**遗留**：不列、不删、不报错。
2. **自动记忆时机 = 后台线程·每轮**：每个 `AgentDone.stop_reason == COMPLETED` 回合后，启 **daemon 线程 fire-and-forget** 抽取，不阻塞输入，异常静默吞到 stderr。
3. **记忆模型 = 默认复用当前对话 provider，可覆盖**：config 留可选 `memory.provider`；为线程安全，抽取器**自建 provider 实例**（不跨线程共享对话 provider）。
4. **指令文件名 = `WENTIAN.md`**（对标 CLAUDE.md 约定）。
5. **自动记忆默认开**（`memory.enabled: true`），留 `memory.enabled: false` 一键关。

## 功能需求 F63–F69（spec.md「以下为 v0.9 新增（记忆与会话）：」）

- **F63: 项目指令文件三层加载 + `@include`**（填 `项目/自定义指令` 槽）——启动时从三处读取手写 Markdown 指令文件并**按优先级高在前拼接**注入系统提示的「项目/自定义指令」模块（该模块 v0.5 起恒返回空、本版起真渲染 `ctx.project_instructions`）：
  - **项目本地覆盖**：`<cwd>/.wentian/WENTIAN.md`（不提交，最高优先级、放最前）
  - **项目根**：`<cwd>/WENTIAN.md`（提交进仓、团队共享，次之）
  - **用户全局**：`~/.config/wentian/WENTIAN.md`（最低、放最后）
  - 每层文件可选，缺失静默跳过；三层均缺则该模块为空。
  - **`@include <相对路径>`**：指令文件中独占一行的 `@include xxx.md` 触发把目标文件内容**内联展开**（相对「包含它的文件所在目录」解析）。约束：**限嵌套深度**（默认 5，超限停止并告警）；**`visited` 集合防环**（同一文件在一条 include 链上重复出现即跳过并告警，不无限递归）；**拦截逃出项目根的路径**（解析后（先解析符号链接再前缀比对，与 v0.6 沙箱同规）若落在项目根之外或为越界绝对路径 → 拒绝该 include 并告警，不读取）。
  - 拼接后总体积设上限（防撑爆上下文），超限按上限截断并告警。
- **F64: 会话存档改 JSONL 追加 + 按 cwd 分区存储**——会话从「单文件全量 JSON 重写」改为**每会话一个 JSONL、按消息追加写**：
  - 路径 `~/.local/share/wentian/projects/<cwd-slug>/sessions/<id>.jsonl`（id 仍为 `YYYYMMDD-HHMMSS-xxxx`）。
  - **追加写**：每轮把新增消息**逐行追加**（不重写全文）；追加快、崩溃只丢最后半行。首行可选 `meta` 记录（id/created_at/provider），其后每行一条 Message。
  - **不维护独立 meta 文件**：ID 取文件名、标题取首条 user 消息行、消息数=数消息行、updated_at 取文件 mtime（或末行）。
  - **分区与列举**：`/sessions` 与 `--continue` **默认只扫当前 `<cwd-slug>` 分区**；`/sessions --all` 跨 `projects/*/sessions/` 全扫。
- **F65: 会话恢复卫生**——`load`/`resume` 时对历史做四道卫生处理，保证恢复后历史**对两家 provider 合法**且**不撑爆窗口**：
  - ① **坏行跳过**：JSON 解析失败的行跳过并告警 stderr，不抛给调用方（JSONL 原生能力）。
  - ② **尾部未配对 tool_call 截断**：历史尾部若是「助手 tool_call 无后续工具结果」的悬空调用 → 截断该未配对部分（送两家 provider 转换不产生 400）。
  - ③ **溢出先压一次**：恢复后用 v0.8 估算判定 `estimate_total > context_window - margin` → **调 v0.8 `Compactor.compact()` 压一次**再进入对话（复用，不重造）。
  - ④ **时间跨度提醒**：距上次 `updated_at` 超阈值（`sessions.resume_gap_reminder_hours`，默认 4h）→ 恢复后**首轮**经 v0.5 `<system-reminder>` 消息通道注入一条**一次性**时间跨度提示（绝不写回持久化 messages）。
- **F66: 过期会话清理**——启动时**惰性清理**：删除当前分区内 `updated_at`（mtime）早于 `sessions.retention_days`（默认 30 天）的会话文件及其 `.artifacts/` 目录；清理失败不致命（告警跳过）。
- **F67: 自动记忆抽取（后台线程·每轮）**——每个 `COMPLETED` 回合后启 **daemon 线程 fire-and-forget**：抽取器取**最近一轮对话**（末次 user + 助手正文，含必要工具活动摘要）+ 现有 INDEX，调 LLM（默认复用当前 provider，`memory.provider` 可覆盖；**自建 provider 实例**）产出**四类笔记**——**用户偏好 / 纠正反馈 / 项目知识 / 参考资料**；**去重交 LLM 判断**（把现有索引喂给它，判「新增 / 更新已有 / 跳过已覆盖」）。抽取**绝不阻塞 REPL 输入**、异常静默吞到 stderr、**绝不中断会话或污染对话历史**；并发写 INDEX **加锁串行**；`/exit` 时最多 `join` 一个短超时不卡退出。`memory.enabled: false` 时整条链路关闭。
- **F68: 记忆分级存储 + 索引启动注入**（填 `长期记忆` 槽）——笔记**用户级与项目级分开存**：
  - **用户级** `~/.config/wentian/memory/`：默认收 `用户偏好`、`纠正反馈`（跨项目）。
  - **项目级** `<cwd>/.wentian/memory/`：默认收 `项目知识`、`参考资料`（LLM 可改判归属）。
  - 每条笔记 = 一个带 **frontmatter**（category / created_at / source_session / tags）的 Markdown 文件；每域一份 **`INDEX.md`** 摘要索引（条目标题 + 一句话，非全文）。
  - **启动注入**：build_app 时读两份 `INDEX.md` 拼进 `ctx.memory` → 填「长期记忆」模块（该模块 v0.5 起恒空、本版起真渲染）；索引**≤ 200 行 / 25KB**（用 v0.8 estimator 卡预算），超限按上限截断。**启动注入一次、不热刷**（保 v0.5 提示词缓存稳定）；本会话新抽的记忆**下一会话**生效——正合「新会话启动时恢复」。
- **F69: 配置扩展**（沿用 v0.7 两层深合并，全可选带默认、缺块/缺字段安全降级不抛异常）：
  - 顶层 `memory:` 块——`enabled`(默认 true) / `provider`(可选，缺省复用当前对话 provider) / `max_index_lines`(默认 200) / `max_index_bytes`(默认 25600)。
  - 顶层 `sessions:` 块——`retention_days`(默认 30) / `resume_gap_reminder_hours`(默认 4)。

## 验收标准 AC75–AC84

- **AC75（F63）三层指令 + @include**：三处放不同 `WENTIAN.md` → 注入「项目/自定义指令」模块、顺序高优先级在前；`@include` 内联目标文件内容；构造 a→b→a 环 → 不无限递归、按 `visited` 跳过并告警；`@include` 指向项目根外/越界绝对路径（含软链接指向项目外）→ 拒绝并告警、不读取；缺文件静默跳过（自动化临时目录）。
- **AC76（F64）JSONL 追加 + 分区**：新会话写到 `projects/<cwd-slug>/sessions/<id>.jsonl`、每轮**追加**新消息行（不重写全文，断言文件按追加增长）；故意写一条坏行 → 恢复时跳过坏行、加载其余、ID 取文件名 / 标题取首条 user / 消息数正确；`/sessions` 与 `--continue` 默认只列当前分区、`--all` 列全部（自动化）。
- **AC77（F65）恢复卫生**：构造尾部「助手 tool_call 无后续结果」→ 恢复时截断该未配对调用、送两家 provider 转换不 400；构造 `estimate>窗口-余量` 的历史 → 恢复时调 v0.8 `Compactor` 压一次后再进入对话；`updated_at` 距今超阈值 → 恢复后首轮注入一条 `<system-reminder>` 时间跨度提醒、且**不写回持久化**（自动化对比 provider 收到的 messages 与 store 落盘 messages）。
- **AC78（F66）过期清理**：构造一个 `updated_at` 超 `retention_days` 的会话 + 一个新的 → 启动后旧的（及其 `.artifacts/`）被删、新的保留；`retention_days` 可配（自动化）。
- **AC79（F67）后台抽取**：一个 `COMPLETED` 回合后台线程调（假 provider 返回固定四类笔记 JSON）→ 抽出笔记按类落到 user/project 目录、写带 frontmatter 的 `.md` + 更新 `INDEX`；注入「抽取必抛异常」的假 provider → **静默吞、会话不中断、对话历史 messages 不被污染、不阻塞下一次输入**（自动化：假 provider + 断言落盘 + 断言异常不崩、不入史）。
- **AC80（F67 去重）LLM 去重**：已有 `INDEX` 含某条 → 再次抽到等价信息 → 把现有索引喂 LLM、它判「已覆盖」则跳过或更新而非重复追加（自动化：脚本化假 provider 返回判重决策，断言不重复追加）。
- **AC81（F68）索引注入**：启动时读 user+project 两份 `INDEX` 注入「长期记忆」模块、内容可见于发给后端的 `system`；索引超 200 行/25KB → 按上限截断；无 memory 时该模块为空、拼装无残渣（自动化断言注入内容 + 上限 + 空槽无残渣）。
- **AC82（F69/N29）配置 + 不破坏**：`memory`/`sessions` 配置块缺失走默认；`memory.enabled:false` 关掉抽取与注入；无 `WENTIAN.md`/无 memory/无历史会话时既有 v0.1–v0.8 测试全绿、行为与 v0.8 一致（自动化 `pytest` 全绿 + 无配置冒烟）。
- **AC83（N30/N31）分层 + 后台安全**：指令/`memory`/会话模块 import 边界（叶子 / 零反向依赖 / 鸭子注入）自动化断言；后台抽取用 daemon 线程不阻塞、自建 provider 不跨线程共享、并发写 INDEX 加锁串行（自动化）；`ruff format --check .` 与 `ruff check .` 通过。
- **AC84（N32）安全**：`@include` 软链接指向项目外被拦（先解析再比对）；记忆/会话落盘不含 api_key（自动化扫描）；项目级 `.wentian/memory/` 在 gitignore 建议内（人工/文档核对）。

## 不做的事（v0.9）

- 不做**向量数据库 / 嵌入检索**（记忆靠启动注入全量索引摘要，不做语义检索）。
- 不做 **RAG 式按需检索记忆**（不在对话中动态召回相关笔记）。
- 不做**团队 / 跨机器记忆同步**（本地单用户，不做云同步/共享）。
- 不做**会话内记忆热刷新**（启动注入一次、保提示词缓存；本会话新记忆下一会话生效）。
- 不做**记忆的图形化管理 / 编辑 UI**（笔记是带 frontmatter 的 Markdown，手动可编辑）。
- 不做**精确 tokenizer**（索引体积/恢复溢出判定复用 v0.8 近似估算）。
- 不做**指令文件实时热重载**（启动加载一次；改了 `WENTIAN.md` 需重启生效）。
- **作废** v0.5 的「不做项目指令文件加载」「不做自动记忆 / 长期记忆提炼」两条——本版正是实现它们。

## 组件设计 C53–C59（plan.md）

> plan.md 的 v0.9 节 = 架构增量(v0.9) + 核心数据结构(v0.9 新增) + 组件设计 C53–C59 + 测试策略(v0.9 增量) + 技术决策 + 风险/边界。各组件给职责 / 对外接口 / 依赖 / 测法。

- **C53 项目指令加载 `prompt/instructions.py`（叶子，stdlib only，置于 prompt 包但不反向依赖 system.py）**：`load_project_instructions(cwd: Path, *, user_home: Path | None = None, cfg) -> str`——解析三层路径、按优先级拼接、递归内联 `@include`（深度上限 + `visited` 防环 + 先解析符号链接再前缀比对拦越界）、体积上限截断。纯函数、临时目录可离线测。被 `cli.build_app` 调用灌进 `PromptContext.project_instructions`。
